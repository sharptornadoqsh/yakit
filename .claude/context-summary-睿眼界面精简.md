# 项目上下文摘要（睿眼界面精简）

生成时间：2026-07-27 16:11:14 +08:00

## 一、目标、范围与交付物

本任务在 `qsh` 分支完成八类显示层精简：代理控制台不展示规则与插件区域、内容规则、下游代理及免配置启动；交互代理不展示高级筛选、进程筛选及表格快捷操作列；漏洞检测不展示专项检测与按组选；插件仓库作者统一显示为 `RuiYan-Admin`；项目工作区不展示存储路径。

改动限定在渲染层、睿眼菜单与集中展示策略。代理表单字段、历史配置、远程过程调用、插件作者原始数据、项目数据库路径和漏洞检测底层实现继续保留，不使用样式属性制造不可见节点。

交付物包括集中展示策略、相关页面改动、回归测试、本地验证结果、操作记录与专项复核报告。

## 二、相似实现分析

- `app/renderer/src/main/src/routes/renyanMenu.ts`
  - 模式：菜单项通过 `featureFlag` 与 `buildRenyanMenu` 统一过滤，显示映射和导航树均由同一模型派生。
  - 可复用：`RenyanFeatureFlag`、默认特性集合、菜单树派生与首个可导航子项选择。
  - 约束：专项检测必须在模型派生阶段排除，不能只在单个菜单组件隐藏。
- `app/renderer/src/main/src/components/HTTPFlowTable/HTTPFlowTable.tsx`
  - 模式：`defaultExcludeColumnsKey` 在列解析阶段排除表格列，并阻止该场景读取远端列缓存。
  - 可复用：现有 `action` 列键、`HTTPFlowRealTimeTableAndEditor` 属性传递链和列解析函数。
  - 约束：交互代理应排除完整操作列，避免残留表头、固定宽度或空白占位。
- `app/renderer/src/main/src/pages/mitm/MITMPage.tsx`
  - 模式：规则与插件区域和主工作区由网格容器及条件渲染共同控制；全屏状态已有单列布局。
  - 可复用：`mitm-plugin-expanded` 单列样式及第二工作区条件。
  - 约束：关闭规则与插件区域后主工作区必须占满可用宽度，不能保留空侧栏。
- `app/renderer/src/main/src/pages/pluginHub/pluginHubList/funcTemplate.tsx`
  - 模式：`HubGridOpt` 是插件仓库在线、我的、回收站和本地卡片的共享展示原语。
  - 可复用：共享作者区域及所有列表调用方。
  - 约束：只改显示文本，不改接口响应、筛选字段、上传身份或所有权判断。
- `app/renderer/src/main/src/pages/pluginHub/hubExtraOperate/funcTemplate.tsx`
  - 模式：`HubDetailHeader` 统一呈现插件仓库详情作者信息。
  - 可复用：详情头共享作者区域。
  - 约束：卡片与详情必须使用相同显示策略。
- `app/renderer/src/main/src/pages/softwareSettings/ProjectManage.tsx`
  - 模式：项目表头由 `projectHeader` 集中定义，再交给虚拟列表渲染。
  - 可复用：表头数组过滤方式。
  - 约束：只排除 `DatabasePath` 列，项目查询、定位、切换与数据库字段保持原状。

## 三、项目约定

- React 组件与类型采用大驼峰，函数和变量采用小驼峰。
- TypeScript 使用两个空格、单引号、无分号和尾逗号。
- 测试位于相邻 `__test__` 目录，使用 Vitest 与 Testing Library。
- 展示差异集中在 `config` 下的睿眼策略模块，业务组件只消费语义化配置。
- 修改只进入当前工作树；本任务不创建提交，也不推送远端。

## 四、可复用组件与接口

- `buildRenyanMenu`：统一派生睿眼菜单、显示映射和导航状态。
- `defaultExcludeColumnsKey`：从表格列解析阶段排除交互代理操作列。
- `mitm-plugin-expanded`：规则与插件区域关闭后的单列工作区。
- `HTTPFlowTableFormConfiguration`：高级筛选状态入口；关闭显示时同步停止读取不可见缓存。
- `RuiYanSegmented`：漏洞检测筛选方式；只保留关键字方式。
- `HubGridOpt` 与 `HubDetailHeader`：插件仓库作者显示的共享边界。
- `projectHeader`：项目列表列定义边界。

## 五、输入输出与集成点

- 输入包括代理历史表单值、远端高级筛选缓存、进程筛选状态、漏洞检测页面信息、插件作者字段和项目描述字段。
- 输出仅改变可见节点、可见菜单、表格列和作者展示文本。
- 配置来源为新增的睿眼展示策略模块；业务数据来源保持现有远程过程调用、接口响应与本地缓存。
- 代理页面通过 `MITMPage`、`MITMServerStartForm`、`MITMLog`、`MITMHijackedContent` 和 `HTTPFlowTable` 集成。
- 漏洞检测通过 `renyanMenu` 与 `YakPoC` 集成；插件仓库通过共享卡片与详情头集成；项目工作区通过表头定义集成。

## 六、测试策略

- 先修改菜单测试并新增展示策略测试，确认旧实现出现预期失败。
- 菜单测试验证专项检测从睿眼导航消失，并验证漏洞检测组默认进入通用检测。
- 展示策略测试验证服务端作者值不会泄露到睿眼作者文本、交互代理排除 `action` 列、旧按组状态归一为关键字方式。
- 相关组件通过定向测试、类型检查和构建验证；静态检索确认目标文字或组件没有可见调用点。
- 最终执行差异空白检查、分支检查、目标测试、完整类型检查和主渲染构建。

## 七、技术选择与风险

- 使用条件渲染和列配置，不使用 `display: none` 或透明度方式。
- 高级筛选入口关闭后，交互代理不再读取其远端缓存，避免无可见控制项的筛选状态影响流量列表。
- 按组选关闭后，旧页面信息中的组选择不参与当前检测参数，默认方式固定为关键字。
- 专项检测从睿眼菜单模型排除；历史活动路由需要回到漏洞检测组的首个可导航页面。
- 插件作者改写限定为显示边界，所有权、评论、协作者和上传身份仍使用真实数据。
- 项目路径列排除后，内部 `DatabasePath` 仍服务于项目打开、定位与数据库管理。
