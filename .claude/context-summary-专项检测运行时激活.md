# 项目上下文摘要（专项检测运行时激活）

生成时间：2026-07-29 10:27:54 +08:00

## 一、目标、范围与交付物

本任务替换专项检测首次下载后的查询重试方案。下载流结束后必须触发真实的运行时插件激活，
让当前引擎连接立即读取新生成的专项关键词分组，并在当前页面显示分类和插件。

改动限定于插件下载完成协议、专项检测页面、Electron 引擎管理桥接及相邻测试。不得重启桌面
程序、重载窗口、要求用户手工重启、增加无限轮询或修改协议和服务端实现。

## 二、真实数据链路

1. `DownloadOnlinePlugins` 在引擎内逐项调用在线插件保存函数，将脚本同步写入当前配置数据库。
2. 下载流的结束事件只在全部保存调用完成后到达 Electron 和渲染页面。
3. 专项关键词分组并非下载时生成，而是由引擎数据库初始化后的回调生成。
4. `QueryYakScriptGroup` 只查询已有分组记录，不会按当前插件重新生成内置分组。
5. 旧实现只重复调用分组查询，因此数据库中没有分组记录时，任何等待时间都不能改变结果。

## 三、原因证据

- 引擎在线插件保存函数直接使用当前配置数据库，没有下载文件等待解压或异步提交阶段。
- 内置专项分类在插件分组模块的数据库后置初始化函数中创建，只随数据库初始化执行。
- 当前协议没有公开通用的插件索引重建、数据库后置初始化或专项分组重建接口。
- 分组查询接口只聚合现有 `plugin_groups` 记录；重置分组接口会删除全部用户分组，不能用于此处。
- 应用重启同时重启内置引擎，数据库后置初始化随之执行，因此重启后分类才出现。

## 四、运行时验证

使用仓库 `bins/yak_windows_amd64.zip` 中的随附引擎和独立临时数据库完成验证：

- 初始专项内置分组记录为零。
- 当前引擎服务启动后保持同一进程号 `20380`。
- 一次性执行引擎帮助命令，复用引擎自身数据库初始化和分组生成逻辑。
- 一次性进程约四秒退出，退出码为零。
- 同一通信连接的专项分组查询由零项变为十三项，包含 Java、PHP、SQL 注入、XSS 等分类。
- 当前引擎进程号在激活前后保持不变，桌面程序和窗口未参与重启。

该结果证明可以采用热激活方式，不需要重启当前引擎。一次性命令必须使用与当前内置引擎一致的
主目录和数据库环境，并设置超时、输出限制和明确的退出码检查。

## 五、相似实现与复用模式

- `app/main/handlers/engineStatus.js`
  - 统一构造本地引擎路径、主目录和数据库环境，并以隐藏子进程启动内置引擎。
- `app/main/handlers/newEngineStatus.js`
  - 为子进程设置明确超时、输出收集、连接探测和任务清理，提供有界生命周期模式。
- `app/main/handlers/yakLocal.js`
  - 复用现有引擎进程枚举，能够按当前端口记录激活前后的引擎进程号。
- `app/renderer/src/main/src/components/layout/YaklangEngineWatchDog.tsx`
  - 区分本地和远程连接，证明本地运行时动作必须拒绝远程引擎上下文。
- `YakitGetOnlinePlugin` 与 `PluginGroupByKeyWord`
  - 下载结束回调已经提供页面级完成边界，专项页面已有分组查询和状态替换能力。

## 六、接口、状态与集成点

- Electron 主进程新增专项插件激活处理器，只接受可信渲染端调用。
- 激活处理器校验当前连接为本机地址，复用内置引擎路径、主目录和数据库环境。
- 主进程在激活前后通过当前通信客户端查询专项分组，并记录数据库路径、引擎进程号和分类数量。
- 预加载桥接只公开专项激活方法，不公开任意命令执行能力。
- 下载完成回调获得阶段文案更新函数；专项页面依次展示数据写入完成、索引刷新和查询验证。
- 激活成功后只执行一次现有专项分组查询，删除查询延时数组和就绪轮询参数。
- 激活或验证失败时保留下载提示；重试只再次执行激活与查询，不再次调用下载接口。

## 七、项目约定与测试策略

- JavaScript 与 TypeScript 使用两个空格、单引号、无分号和尾随逗号。
- 主进程测试位于 `app/main/__test__`，渲染测试位于相邻 `__test__`，统一使用 Vitest。
- 先建立一次性进程成功、非零退出、超时终止和输出限制测试。
- 再建立专项下载必须先调用运行时激活、随后只查询一次分组的页面测试。
- 下载组件测试阶段文案回调、异步等待、错误区分、重复结束和卸载清理。
- 下载组件测试失败后重试、下载调用次数和最终成功关闭。
- 最终执行定向测试、类型检查、目标规则检查、格式检查、差异检查和临时运行时复验。

## 八、依赖与风险

一次性初始化会执行引擎既有数据库后置回调，运行时验证证明其可与当前引擎并存并使当前连接立即
看见新分组。风险集中在数据库环境不一致、远程引擎误调用、子进程悬挂和错误提示模糊；分别通过
复用启动环境、本机地址校验、有界超时和分阶段错误信息约束。

当前工具集中未提供任务管理器，使用仓库实施计划和会话计划替代。外部代码搜索受匿名接口限流，
真实原因与方案依据来自引擎源码、仓库随附二进制和独立临时数据库动态验证。

## 九、充分性结论

现有证据已经覆盖三个以上相似实现、下载写库到分组查询的完整链路、当前引擎可见性、进程与数据库
边界、测试框架和回退方式，可以进入测试先行的最小实现阶段。
