# 项目上下文摘要（专项检测首次下载自动刷新）

生成时间：2026-07-28

## 一、目标、范围与交付物

本任务修复专项检测首次下载云端插件后，当前页面仍显示空数据、必须重启应用才出现插件的问题。
下载流成功结束后，页面需要重新查询本地插件关键词分组，并让现有插件列表依据最新分组继续查询插件。

改动限定于专项检测页与现有下载组件的完成回调时序。不得使用应用重启、渲染器重载、页面跳转、
固定等待时间或全局缓存清理。已有菜单、关键词模式、纯名称插件行及其他睿眼界面策略保持不变。

## 二、下载、导入与渲染链路

1. `YakPoC.tsx` 中的 `PluginGroupByKeyWord` 在关键词分组为空时显示一键下载入口。
2. `YakitGetOnlinePlugin` 调用 `DownloadOnlinePlugins`，并监听任务令牌对应的数据、错误与结束事件。
3. `app/main/handlers/pluginTool.js` 将请求转交引擎远程过程调用；只有下载流真正结束时才发送结束事件。
4. 专项检测分类通过 `QueryYakScriptGroup` 查询，插件列表通过 `QueryYakScript` 查询。
5. 分类写入 React 状态后，现有列表组件按照选中分类重新读取插件，无需增加新的后端接口。

## 三、原因证据

- `PluginGroupByKeyWord` 的常规初始化只随视口首次进入执行，页面保持挂载时不会再次触发。
- 当前代码没有使用下载组件已有的 `onFinish` 完成回调，而是在 `setVisible` 中延迟二百毫秒调用初始化。
- `setVisible` 同时代表取消和成功关闭，不能证明资源已经导入；固定延时也不能表达导入完成条件。
- 初始化查询未被调用方等待，且只在旧响应为空时写入响应状态，无法可靠替换过期分类。
- 仓库内没有发现此页面依赖的应用启动期插件缓存，也没有适用于该流程的索引重建接口。
- 应用重启会重新挂载页面并再次执行初始化，因此能够解释当前观察到的重启后恢复现象。

## 四、相似实现与可复用模式

- `app/renderer/src/main/src/components/layout/UILayout.tsx`
  - 使用 `YakitGetOnlinePlugin` 的 `onFinish` 表达下载成功后的业务动作，证明该回调是现有完成协议。
- `app/renderer/src/main/src/pages/KnowledgeBase/compoment/ImportModal.tsx`
  - 导入完成后等待数据存在性查询，再结束加载与关闭界面，体现异步刷新应属于完成流程。
- `app/renderer/src/main/src/pages/pluginHub/pluginHubList/HubListTeam.tsx`
  - 使用请求序号与当前上下文防止过期异步响应覆盖新状态，可用于专项分类刷新保护。
- `app/renderer/src/main/src/pages/pluginHub/group/PluginOperationGroupList.tsx`
  - 插件下载后重新查询依赖的分组数据，说明下载完成后更新分组属于既有页面模式。
- `app/renderer/src/main/src/pages/simpleDetect/SimpleDetect.tsx`
  - 下载组件结束后触发插件分组刷新，说明无需修改插件执行接口。

## 五、项目约定与复用边界

- React 组件和类型采用大驼峰，函数与变量采用小驼峰。
- TypeScript 使用两个空格、单引号、无分号与尾随逗号。
- 测试位于相邻 `__test__` 目录，使用 Vitest、Testing Library 与 `jsdom`。
- 复用现有下载远程过程调用、任务令牌事件、`onFinish`、分类查询与插件列表查询。
- 不新增依赖、不修改协议文件、不改变下载数据库结构或其他页面的分组能力。
- 生产代码与任务文档只通过 `apply_patch` 修改。

## 六、接口、状态与集成点

- 下载组件的 `onFinish` 类型允许返回承诺，并在结束事件中等待该承诺完成。
- 专项检测把显隐回调恢复为单纯控制弹窗，把重新查询绑定到 `onFinish`。
- 分类查询每次成功都用新响应替换旧响应，并继续同步父级选择状态。
- 页面使用请求序号和卸载标记忽略过期结果，防止快速重复动作或卸载后的状态写入。
- 刷新失败时保留可恢复界面并显示明确错误，不把失败误报为下载流失败。

## 七、测试策略

1. 扩展专项检测组件测试：首次分类为空，打开下载弹窗，触发完成回调后返回新分类。
2. 在生产实现修改前执行测试，要求它因没有传入完成回调而失败。
3. 为下载组件增加完成时序测试：结束事件必须立即调用异步刷新，并在刷新完成前不关闭弹窗。
4. 覆盖刷新失败路径，要求弹窗保持可见且不会重复触发成功关闭。
5. 实施后执行新增测试、相关专项检测测试、类型检查、规则检查与差异检查。

## 八、依赖关系与风险

依赖方向为下载流结束事件到下载组件完成回调，再到专项分类查询、React 分类状态和现有插件列表查询。
主要风险是共享下载组件时序影响其他调用方、过期请求覆盖新状态及刷新失败后界面不可恢复。
回调保持可选且同步回调兼容原行为；时序、失败和页面刷新分别由组件测试约束。
