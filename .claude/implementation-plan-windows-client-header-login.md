# Windows 客户端身份请求头修复计划

生成时间：2026-07-27 15:31:25 +08:00

## 目标

修正桌面端协作身份请求头的值生成规则，使合法 ASCII 行为兼容，异常电脑名称得到确定性安全 ASCII，并确保 Axios 请求能够越过 Node.js 请求头构造阶段。

## 修改范围

- 修改 `app/main/__test__/collaborationClientIdentity.test.js`，覆盖全部指定输入和最终头校验。
- 修改 `app/main/collaborationClientIdentity.js`，统一生成并校验请求头值。
- 更新 `.claude/operations-log.md`、`.claude/coding-log.md` 与 `.claude/verification-report.md`。
- 不修改 `app/main/httpServer.js`、账号密码处理、依赖、锁文件、生成产物和安装配置。

## 任务一：建立失败回归测试

- 保留既有首次生成与覆盖行为断言。
- 增加普通英文、中文、表情、控制字符、空名称和超长名称测试。
- 增加非法持久化客户端标识重新生成测试。
- 增加全部 `X-Yakit-*` 值通过 `http.validateHeaderValue` 的测试。
- 执行目标 Vitest，预期当前实现因中文值、控制字符值、超长值和非法标识处理不符合契约而失败。

## 任务二：实现统一安全值生成

- 定义可打印 ASCII 范围与二百五十五字符上限。
- 对合法 ASCII 值保留既有首尾空白处理和原始内容。
- 对异常值使用内置 SHA-256 生成固定格式摘要。
- 在转换前检查持久化客户端标识，使非法值必定触发重新生成。
- 五个身份头均通过统一生成函数和 `validateHeaderValue`。
- 不调整请求拦截器与 online 数据结构。

## 任务三：验证与复核

- 执行目标 Vitest并确认全部测试成功。
- 对两个修改文件执行语法与格式检查。
- 执行仓库相关静态检查和 `git diff --check`。
- 启动本地 HTTP 服务，通过 Axios 发送使用中文电脑名称生成的身份头，确认服务端收到请求。
- 同步 CodeGraph，检查受影响测试与最终差异。
- 按需求、代码质量、测试覆盖、规范遵循、架构一致与风险六个方面生成验证报告。

## 风险控制

- 客户端标识校验与普通头值转换保持独立，防止非法持久化标识被摘要结果误判为有效标识。
- 摘要输入采用转换前完整字符串，确保控制字符与超长输入不会因删除或截断产生相同结果。
- 摘要输出固定小于既有长度上限，且字符集合限定为 ASCII。
- 修改只触及身份值来源，不扩大到错误提示、登录表单或网络重试。

## 验收标准

- 中文名称的原始失败命令不再产生 `ERR_INVALID_CHAR`。
- 普通英文名称的五个头值与现有行为一致。
- 指定异常输入均产生确定性安全值。
- 非法客户端标识重新生成并写入配置。
- 全部身份头通过 Node.js 请求头校验。
- 目标测试、相关静态检查和本地 Axios 发送验证成功。
- Git 中不存在无关文件、依赖或生成产物变化。
