# 睿眼界面精简实施计划

生成时间：2026-07-27 16:11:14 +08:00

## 一、方案

新增集中睿眼展示策略，集中声明代理、漏洞检测、插件仓库和项目工作区的可见性及作者显示规则。业务组件通过条件渲染、菜单特性过滤、表格列排除和表头过滤消费该策略。

## 二、执行序列

1. 建立失败测试，覆盖专项检测移除、默认漏洞入口、作者改写、交互代理操作列排除和旧按组状态归一。
2. 新增集中展示策略，并使菜单模型消费专项检测特性。
3. 调整代理控制台的规则与插件区域、启动表单行、交互代理筛选入口和操作列。
4. 调整漏洞检测按组选状态，使不可见组选择不进入检测参数。
5. 调整插件仓库卡片与详情作者显示，并排除项目存储路径列。
6. 执行定向测试、格式、类型、静态检索、差异检查和主渲染构建。
7. 完成操作记录、编码记录和专项复核报告。

## 三、验收标准

- 规则与插件区域及相关插件开关没有渲染节点，代理主工作区占满原侧栏空间。
- 内容规则、下游代理、免配置启动、高级筛选、进程筛选和三个快捷操作按钮没有渲染节点。
- 交互代理不读取不可见高级筛选缓存，操作列没有表头或宽度占位。
- 睿眼菜单不含专项检测，漏洞检测组默认进入通用检测。
- 漏洞检测不含按组选，旧组选择不影响当前检测参数。
- 插件仓库卡片与详情作者均显示 `RuiYan-Admin`，原始作者数据不被修改。
- 项目工作区不含存储路径列，`DatabasePath` 字段和项目能力保持。
- 定向测试、完整类型检查、差异空白检查和主渲染构建成功。

## 四、回退方式

所有显示变化由集中策略控制。恢复某项展示时修改对应策略值即可；底层字段、接口和业务组件没有删除，无需数据迁移。
